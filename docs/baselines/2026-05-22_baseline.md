## Recovery procedure

If bot performance degrades materially below baseline metrics (sustained
WR < 40% over n≥100, or cumulative PnL going negative across a full
trading day), use this to re-anchor:

### Tier 1 — config-only recovery (no code change)

```bash
# Toggle off recent calibration layers in config/settings.yaml:
lane_calibration:
  beta_veto_max_mean: 0           # disable global β-veto
  per_lane_thresholds:
    enabled: false                # disable per-lane overrides
    recompute_on_settle: false    # stop auto-rewriting thresholds
ai:
  decision_layer:
    use_shadow_portfolio: false   # back to selective AI mode
```

Restart bot. This returns to plain α-correction + momentum guards.
**Closest fast match to baseline behavior.**

### Tier 2 — git revert to baseline commit

If Tier 1 doesn't restore performance, revert to the last commit before
the calibration session work:

```bash
git log --oneline | head -20
# Find commit BEFORE 2791e48 (the calibration commit)
git revert 2791e48              # undoes calibration session work
# Or hard reset (DESTRUCTIVE — only if certain):
git reset --hard 62486e6        # back to BTC decouple + guards (baseline-era)
```

After revert, restart bot. Verify against ghost log that vetoed lanes
have stopped being suppressed.

### Tier 3 — full restore to 62486e6 baseline

If both above fail and bot is in active loss:

```bash
git stash                       # save current uncommitted edits
git checkout 62486e6 -- src/analysis/lane_calibration.py \
                         src/analysis/ghost_calibration.py \
                         src/main.py \
                         config/settings.yaml
# This restores the EXACT calibration files from before any session work
```

Note: `62486e6` is the BTC decouple commit which IS doctrinally correct
(alts not decided by BTC) and was empirically validated. The baseline
session ran briefly under it. Earlier baseline (`62486e6^`) reintroduces
the pre-decouple side selection which has its own known issues
(BTC-deciding-alt anti-pattern per `feedback_alts_not_decided_by_btc.md`).

## Re-calibration after restoration

Once back at a working baseline:

1. Let ghost log accumulate fresh paired data for 24-48 hours
2. Run `python3 scripts/compute_lane_thresholds.py --report` to see what
   the ghost data now recommends
3. Compare against this baseline's per-cell breakdown — which lanes were
   profitable then and are still profitable, which were already showing
   death-spiral
4. Re-enable layers incrementally:
   - First: `per_lane_thresholds.recompute_on_settle: true` (inspection-only)
   - Then after review: `per_lane_thresholds.enabled: true`
   - Last: global β-veto if needed
